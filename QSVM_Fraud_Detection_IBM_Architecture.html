QSVM fraud detection on IBM Quantum — architecture

A hybrid pipeline for classifying mobile-money fraud: classical data preparation and SVM training on a laptop, quantum-kernel circuits executed on a real IBM quantum computer through Qiskit Runtime, compared fairly with a classical RBF-kernel SVM.

CLASSIFY

QSVM

Compare on the same 20 test rows

vs classical RBF SVM (C = 1, γ = scale) and the noise-free ideal QSVM

K(a, b) = |⟨ψ(a)|ψ(b)⟩|² ≈ count(“0000”) ÷ shots

Identical transactions return to 0000 on every shot; different ones return less often. On IBM Heron the circuit compiles to rz · sx · cz gates: 22 two-qubit gates, depth 129. Bandwidth and C are tuned with cross-validation on the free exact simulator, so the QPU is used only once, for the final kernel.

NO ADVANTAGE YET

The tuned RBF SVM matches or beats both QSVMs; hardware noise mainly costs recall.

SCALE

Circuits grow as N²: 50 rows → 1,035 circuits; 1,000 rows → about 500,000.

SMALL SAMPLE

Only 6 fraud cases in the test set; synthetic data with 30% fraud.

Figures from the local run; a real IBM run fills the third row with its own measured results. Precision is 1.00 for all three models (no false alarms on this test set); the differences are in recall. One fraud case moves recall by about 17 points, so treat small gaps as ties. Next steps: more shots, stronger error mitigation, shallower circuits, and real imbalanced data.
